Если ход улучшает решение, принимаем всегда, иначе — с вероятностью exp(-delta / T). Температура убывает геометрически, параметры подбирал грубо руками под разные размеры входа, поэтому пока большие тесты не кушает. Есть куда оптимизироваться, до конца месяца буду тыкаться.

### Моя формулировка

Ищу гамильтонов цикл минимальной длины. Чем меньше суммарная длина ребер по всему циклу, тем лучше. Решение храню как перестановку вершин. 
Получается, на каждом шаге я выбираю две позиции в текущем маршруте и разворачиваю участок между ними. Если длина становится больше, то по отжигу случайно могу принять этот ход.


### Описание экспериментов

1. Самое исходное решение состояли из жадной nn инициализации, запускал из нескольких случайных городов, вычислял матрицу расстояний для n <= 5000
2. Далее крутил температуру – уменьшил в 10 раз, замедлил охлаждение с 0.95 до 0.999999.
    Тут получил 335330
3. После этого сделал полный 2-opt: перебирал все пары ij и разворачивал сегмент, если это улучшало решение. Для больших n разворот не делал, т.к. это редко что то улучшает, поэтому ограничил сегмент 500 элементами. 
4. Сделал дополнительно or-opt, включал его на n <= 300, tsp_200_2 деградировал с 29874 до 30560. Поэтому снизил порог or-opt еще до 150. Тут получил 535330.

Еще один подход, попробовал локальный поиск с multistart nn с top-5 туров.
1. На каждом кандидате делал 2-opt -> 3-opt -> 2opt
2. Брал 5 лучших туров
3. Для больших n делал 150 и 32 стартов, для маленьикх n
4. После локального поиска запускал отжиг на 2-opt, но с тестами не помогло

Такой подход дал 333330 баллов. По последнему тесту у меня 0 баллов, т.к. он не укладывается в 5 минут. По правилам курса это не решение, соответственно, я не засчитывал никакой свой результат
